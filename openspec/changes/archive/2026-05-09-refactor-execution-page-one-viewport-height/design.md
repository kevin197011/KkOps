# Design: 运维执行页——高度一屏、宽度不变、功能块重规划

## Context

用户澄清：不需要左右分栏，**宽度维持原样**（单栏、居中、maxWidth 约 1200），只需**高度占一屏**，并**重新规划每个功能块的布局**，使整页在典型视口内高度不溢出、操作更便捷。

## Goals / Non-Goals

### Goals
- 保持内容区宽度不变（单栏、maxWidth、居中）。
- 整页高度在一屏内（根容器使用 viewport 高度，长内容区 maxHeight + 内部滚动）。
- 重新规划各功能块排布（模式、脚本、主机、选项、执行按钮、结果）使一屏内合理展示。

### Non-Goals
- 不采用左右分栏（配置左、结果右）。
- 不改变页面整体宽度或居中方式。

## Decisions

### 1. 整体宽度与结构

- **恢复单栏**：撤销当前左右 Col 分栏，内容区恢复为单栏容器，`maxWidth: 1200`、`margin: 0 auto`、`width: 100%`。
- **根容器高度**：使用 `minHeight: calc(100vh - <header 等>)`，保证一屏高度可用。

### 2. 功能块布局重规划（单栏宽度内）

在单栏内重新排布，使垂直空间压缩、一屏可容纳：

- **方案 A（推荐）**：  
  - 第一行：**模式选择** 与 **执行选项** 并排（Row 两 Col），减少纵向占用。  
  - 第二行：**脚本编辑区** 与 **主机选择区** 并排（Row 两 Col），各设 maxHeight + 内部滚动。  
  - 第三行：**执行按钮**（可居中或左对齐）。  
  - 第四行：**执行结果区**，占剩余高度，maxHeight + 内部滚动。
- **方案 B**：  
  - 保持自上而下顺序，但缩小间距、为脚本/主机/结果区统一设 maxHeight + 内部滚动，不改变块顺序。

**决策**：采用方案 A，通过「模式+选项同一行」「脚本+主机同一行」压缩高度，使一屏内完整呈现配置与结果。

### 3. 高度约束

- **脚本编辑区**：maxHeight（如 22vh 或 200px），内部 overflow: auto。
- **主机列表**：maxHeight（如 220px 或 24vh），内部 overflow: auto。
- **执行结果区**：占剩余可用高度，maxHeight 或 flex: 1 + minHeight: 0，内部 overflow: auto。
- 模式选择、执行选项、执行按钮：不设固定高度，保持紧凑。

### 4. 响应式

- 宽度小于某断点（如 992px）时，脚本区与主机区可由「并排」改为「上下堆叠」，仍保持宽度不变与高度约束，使一屏内可见。

## Risks / Trade-offs

| 风险 | 缓解 |
|------|------|
| 脚本/主机并排后单块变窄 | 使用 Col 比例（如 1:1 或 3:2），保证最小宽度可读 |
| 小屏并排拥挤 | 断点以下改为上下堆叠 |

## Migration Plan

1. 撤销 ExecutionOperatorPage 的左右分栏，恢复单栏 + maxWidth。
2. 按上述重规划调整各功能块（模式+选项一行，脚本+主机一行，按钮，结果）。
3. 为脚本区、主机列表、结果区设置 maxHeight 与内部滚动。
4. 根容器使用 viewport 高度。
5. 断点以下脚本/主机改为上下堆叠。
